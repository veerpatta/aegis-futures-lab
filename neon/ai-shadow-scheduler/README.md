# Aegis shadow scheduler on Neon

This standalone Function is an alternative when GitHub Actions secrets cannot be provisioned. It does not hold the OpenAI key and cannot place trades. It verifies a Neon scheduled delivery and forwards it to the fixed Aegis production endpoint with the dedicated `AI_SHADOW_CRON_SECRET` bearer. It ignores stale trigger deliveries and does not follow redirects. The production Vercel endpoint enforces its own authentication, registered-study, freshness, budget and one-attempt rules.

The trigger's provenance depends on the **Neon native Functions edge**, which strips client-supplied `x-neon-*` headers. Do not deploy this handler behind another proxy or treat the parser as a signature verifier there. Trigger IDs are not secrets. The included `neon.ts` creates the new `aegisshadow` function and `aegis-shadow-forward` schedule in the selected branch; the schedule starts **disabled**. Verify the plan carefully: do not replace or disable the existing `aegisexp` function or its triggers. Set the production Vercel `AI_SHADOW_CRON_SECRET` to the same newly generated value. Never put the secret in source, logs, a browser bundle, the endpoint URL, or command arguments.

1. Follow [Neon's Function instructions](https://neon.com/docs/compute/functions/get-started) to install and authenticate the current Neon CLI; link this directory to the intended Aegis project and main branch. Install the locked dependencies using `npm ci` in this directory.
2. Put `AI_SHADOW_CRON_SECRET` in a private, gitignored environment file with owner-only permissions. Use a long, randomly generated string, at least 32 bytes. Configure the identical value on Vercel server production without printing it. Do not place the OpenAI key in Neon.
3. Check `neon config plan` with that environment file and review every change. Apply the dedicated config with `neon deploy --env <private-env-file>` only after verifying it will not affect unrelated resources. The declared schedule runs at minutes 7, 22, 37 and 52 each hour and is disabled on first deployment. Confirm with `neon triggers list` that the correct new trigger and function exist, and that the learner's existing triggers remain intact.
4. Verify both AI database migrations and the restricted role, register the exact study configuration, and set Vercel `AI_SHADOW_STUDY_ID`, `AI_SHADOW_ENABLED=true`, `OPENAI_API_SECRET`, and `AI_DATABASE_URL`. Ensure the source capture engine runs with the same study ID. Then enable **only** the `aegis-shadow-forward` trigger by its ID with `neon triggers enable <id> --branch main`. Disable the GitHub shadow caller if previously enabled, to avoid redundant calls.
5. Verify the scheduled invocation and the private study events without echoing credentials. An empty study is expected until fresh eligible opportunities arrive. A 502 means the Vercel service did not accept the request; read server logs without logging secrets. Do not bypass freshness checks to backfill.

Use `neon triggers disable <id> --branch main` to stop the schedule. Rotate the dedicated secret on both services together if exposed. Redeploying this config declares the trigger disabled, so inspect the plan before applying updates.

On a 31-day month this schedule invokes the Function about 2,976 times; requests, runtime, and network egress are billed under the project's Neon plan. As of the [Neon plan documentation](https://neon.com/docs/introduction/plans#functions), Free includes 1 million invocations, 10 active capacity-hours, and 400 waiting capacity-hours per project per month; other Functions in the same project share the allowance, and paid usage has separate rates. A timed-out call can wait up to 45 seconds. Check current plan, existing project usage and prices before enabling; this compute cost is separate from the $25 OpenAI budget.
