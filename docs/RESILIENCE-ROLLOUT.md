# Resilience rollout — gated; do not arm yet
The existing Aegis clock and Actions remain primary. The new standby is a build candidate, not a verified production engine. The prior read-only watchdog remains live. The private guard is disabled by default. Its owner token is deliberately **non-expiring**: an interrupted worker might still be issuing database writes. Release after a crash only after verifying the old process is gone and auditing the last completed batch. This is a durable mutex, not per-write fencing. Do not enable parallel automatic writes without complete fencing and isolation tests.

1. Build on the PR with no database credentials, run all regression and parity tests, inspect the standalone bundle and verify the original research hash. Never run run-live locally against production.
2. Apply the additive runner_guard migration only after testing it in a separate synthetic-data database. Verify the existing production workflow credential can read it.
3. Deploy the standby bundle as a separate Neon function with AEGIS_STANDBY_ENABLED=false. Do not update or enable the old aegisexp function until its v3-compatible bundle and independent jobs pass tests.
4. Run a seven-day isolated soak test with fixed inputs and compare all signals, research records, learner ledger, watermarks and guard behaviour. Verify all other database writers (owner controls, nightly learning, research workflows), holiday skips, fresh/replay classification, and 30% free-tier headroom. Inspect environment flags; never copy or print secrets.
5. Before any production activation, drain all old writers, apply database-enforced fencing or otherwise prove no unguarded writer can overlap, confirm every active workflow uses the approved code, and set approved_standby_sha to the exact reviewed build. Enable primary guard and standby only after explicit acceptance of all gates. If deployment/DB fails, fail closed; never clear an unknown owner automatically.
6. Add a separately hosted watchdog (Cloudflare) with read-only completion checks, independent alerts, deduplication, calendar and quota checks. Existing external hourly monitoring is supplementary.
7. Rollback: disable standby triggers and env; wait for any owned execution to terminate, inspect guard and publication; restore primary-only operation after verifying all writers are stopped. Do not reset campaign, delete evidence or bypass freshness.

The build-only CI includes a disposable local PostgreSQL concurrency test (10 simultaneous contenders). Bundle handoff prints only the public source ZIP, never environment values. The existing workflow-order contract is retained by testing the extracted ordered pipeline, including failed engine/publication stages. A green build and these tests do not establish full market-data or ledger parity.
