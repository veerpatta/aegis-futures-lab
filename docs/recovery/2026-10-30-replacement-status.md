This is new implementation, not the lost original code. The migration pins the sole existing unbanned administrator as owner, and refuses to run if that precondition is false. Private journal and CRM RLS checks that pinned identity, current administrator role and ban status. The web API verifies the Neon JWT and rechecks that role in the database. The trusted worker rechecks and locks the account before acting. Public pages remain readable. Neon Auth provider-level signup endpoints are unchanged.

New production permissions proposed: `authenticated` may execute `public.aegis_is_owner()` (a boolean-only security-definer check); `aegis_ai` may select `public.admin_control_authorized` and select the command queue and insert only its id, owner, action, reason and expected campaign columns. The browser roles cannot read or write that queue. The service cannot update or delete commands. These grants are needed for the existing restricted server connection to verify the current owner and enqueue or list commands; the privileged worker completes them. They do not add login credentials or role memberships. They are a permissions expansion and are not authorized for production by the earlier no-expansion constraint without specific action-time confirmation.

The worker processes commands on a genuine tick trigger. It rechecks current administrator status, shares locks with tick and learning, refuses stale campaigns, and records a result atomically. Pause keeps managing virtual positions. Stop refuses while a virtual position or pending fill remains; a new campaign also requires no remaining positions and preserves the prior ledger. Commands may remain pending over the weekend or if the scheduler is unavailable. This work does not initiate real trades or paid AI calls.
