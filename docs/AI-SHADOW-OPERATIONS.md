# AI shadow study operations

The shadow study is separate from the existing paper account. It uses delayed data and its results do not prove a trading edge. The signal workflow selects the preregistered study named below by default; processing remains off until separately configured.

The application ledger covers only Aegis calls, not other OpenAI project usage. Set and monitor a provider-side project budget separately. The server's verified price entries expire at 00:00 UTC on 30 November 2026; once expired, paid calls stop safely. Before then, check current provider prices and update the matching price entries and verification dates in both research and shadow routes, then test and redeploy. A model or prompt change for the shadow study also requires a new registration and observation period.

The separately deployed [Neon scheduler](../neon/ai-shadow-scheduler/README.md) can replace the GitHub scheduler when Actions secrets are unavailable. Use one scheduler at a time; do not change the existing learner function or its triggers. The Neon scheduler's compute usage is separate from OpenAI charges.

1. Apply the AI research, shadow bar and AI role migrations in order, after checking the target database and roles. Provision a restricted `AI_DATABASE_URL` for the Vercel server with the grants in the AI role migration. Keep database credentials server-side.
2. Register a new immutable `ai_shadow_studies` row before collecting evidence. The model, prompt and feature versions must match `SHADOW_MODEL`, `SHADOW_PROMPT_VERSION` and `SHADOW_FEATURE_VERSION` in `lib/ai-shadow/processor.ts`; its exact JSON config must match `SHADOW_STUDY_CONFIG` in `lib/ai-store/shadow.ts`. Changes require a new study ID and a fresh observation period. The collector never backfills old results as fresh observations.
3. The reviewed signal workflow defaults `AI_SHADOW_STUDY_ID` to `openai-forward-20261030-v1` and `AI_SHADOW_CAPTURE_ENABLED` to `true`; it will capture only if that exact study is registered. A GitHub repository variable can explicitly override either value. Best-effort snapshot and direct-feed bar capture runs during the existing signal-engine schedule. An archive fallback is not accepted as a fresh Yahoo receipt. Paused ideas are retained as observations but are skipped before model processing and excluded from trade and control results.
4. Generate a separate random scheduler secret, for example with `openssl rand -hex 32`. Store the same value as the GitHub Actions secret and the Vercel server environment variable `AI_SHADOW_CRON_SECRET`. Do not put it in a repository variable, logs, or source code. The scheduled client accepts 32–128 letters, digits, underscores or hyphens.
5. Set `AI_SHADOW_STUDY_ID` to the same ID and `AI_SHADOW_ENABLED=true` in Vercel, along with the server-only `OPENAI_API_SECRET` and restricted `AI_DATABASE_URL`. Deploy the environment change. Processing checks the immutable study configuration and the shared budget before a provider call.
6. Set GitHub repository variable `AI_SHADOW_SCHEDULER_ENABLED=true`. The separate scheduler job calls the fixed production endpoint once per existing 15-minute engine schedule and processes at most one pending idea per call. It uses only the scheduler secret, never the OpenAI key. The signal engine continues if the job fails. Inspect the workflow warnings and private study events for failures.

To stop processing, unset `AI_SHADOW_SCHEDULER_ENABLED` or set `AI_SHADOW_ENABLED` to a value other than `true`. To stop collection too, set the GitHub repository variable `AI_SHADOW_CAPTURE_ENABLED` to `false`, or change its workflow fallback to `false` in a reviewed commit. Rotate the scheduler secret in both systems together if it is exposed. Bar corrections are detected over a rolling 24-hour feed window; a known revision invalidates dependent results. Valid cancelled fills count as zero for each control. The comparison is modeled USD per opportunity, not portfolio returns. Missing receipts or provider errors are not evidence of a profitable trade.
