# AI shadow study operations

The shadow study is separate from the existing paper account. It uses delayed data and its results do not prove a trading edge. Both collection and processing are off until configured.

1. Apply the AI research, shadow bar and AI role migrations in order, after checking the target database and roles. Provision a restricted `AI_DATABASE_URL` for the Vercel server with the grants in the AI role migration. Keep database credentials server-side.
2. Register a new immutable `ai_shadow_studies` row before collecting evidence. The model, prompt and feature versions must match `SHADOW_MODEL`, `SHADOW_PROMPT_VERSION` and `SHADOW_FEATURE_VERSION` in `lib/ai-shadow/processor.ts`; its exact JSON config must match `SHADOW_STUDY_CONFIG` in `lib/ai-store/shadow.ts`. Changes require a new study ID and a fresh observation period. The collector never backfills old results as fresh observations.
3. Set GitHub repository variable `AI_SHADOW_STUDY_ID` to that registered ID. This enables best-effort snapshot and direct-feed bar capture during the existing signal-engine schedule. An archive fallback is not accepted as a fresh Yahoo receipt.
4. Generate a separate random scheduler secret, for example with `openssl rand -hex 32`. Store the same value as the GitHub Actions secret and the Vercel server environment variable `AI_SHADOW_CRON_SECRET`. Do not put it in a repository variable, logs, or source code. The scheduled client accepts 32–128 letters, digits, underscores or hyphens.
5. Set `AI_SHADOW_STUDY_ID` to the same ID and `AI_SHADOW_ENABLED=true` in Vercel, along with the server-only `OPENAI_API_SECRET` and restricted `AI_DATABASE_URL`. Deploy the environment change. Processing checks the immutable study configuration and the shared budget before a provider call.
6. Set GitHub repository variable `AI_SHADOW_SCHEDULER_ENABLED=true`. The separate scheduler job calls the fixed production endpoint once per existing 15-minute engine schedule and processes at most one pending idea per call. It uses only the scheduler secret, never the OpenAI key. The signal engine continues if the job fails. Inspect the workflow warnings and private study events for failures.

To stop processing, unset `AI_SHADOW_SCHEDULER_ENABLED` or set `AI_SHADOW_ENABLED` to a value other than `true`. To stop collection too, unset the GitHub `AI_SHADOW_STUDY_ID`. Rotate the scheduler secret in both systems together if it is exposed. Bar corrections are detected over a rolling 24-hour feed window; a known revision invalidates dependent results. Missing receipts or provider errors are not evidence of a profitable trade.
